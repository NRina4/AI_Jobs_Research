# Отчёт по лабораторной работе № 1

## 1. Цель работы

Развернуть каркас проекта `AI_Jobs_Research` и настроить инструменты контроля качества: управление зависимостями,
статическую типизацию, линтер, тесты, конфигурацию, логирование, CLI и непрерывную интеграцию.

## 2. Результат работы

Создан проект в `src-layout` с менеджером зависимостей `uv` и фиксацией версий в `uv.lock`. Настроены: конфигурация
через `pydantic-settings` с префиксом `RG_`, логирование, CLI на Typer с командами `version` и `check-config`, строгая
статическая типизация Mypy (`strict = true`), линтер и форматтер Ruff, тесты и Pre-commit. Добавлены заготовки модулей
под будущие лабораторные: `models`, `sources`, `storage`, `pipelines`, `api`.

**Выполненный уровень — базовый+.** Все критерии C1–C10 реализованы. Пункты уровня «базовый++» не выбраны.

## 3. Проверка качества

Локальные проверки Ruff, Mypy и Pre-commit завершились успешно. Pytest: 8 тестов пройдены, покрытие кода составило
85,19 % при пороге 70 % (зафиксирован в `pyproject.toml`). GitHub Actions выполняет линтинг, проверку форматирования,
типизацию и тесты. В README добавлены инструкции по установке, настройке, запуску CLI и проверок.

## 4. Затруднения и принятые решения

- Pre-commit при первом запуске выявил замечания по оформлению; после автоисправлений повторный прогон прошёл успешно.
- Строгий Mypy потребовал точечных настроек для сторонних библиотек и соблюдения аннотаций во всех модулях.
- Тесты изолированы от локального `.env` и переменных окружения через фикстуру `isolated_env`, чтобы результаты не
  зависели от машины разработчика.
- Покрытие настроено по пути `src/research_graph`, чтобы процент считался по реальному коду, а не по кэшам.

## 5. Решения и отличия от образца

- Уровень логирования берётся из конфигурации приложения (`setup_logging` принимает уровень из `Settings`), а не
  передаётся отдельно при каждом вызове.
- Логи направляются в `stderr`, чтобы не смешиваться с выводом CLI.
- Секретный токен маскируется в `check-config`; `.env` исключён из Git, вместо него хранится `.env.example`.
- Использован `--strict-markers` в pytest, чтобы опечатки в маркерах не проходили молча.

## 6. Вывод

Подготовлен проверяемый и расширяемый каркас проекта. Настроенные инструменты качества, тестирование и CI создают основу
для дальнейшей разработки исследования рынка вакансий в сфере искусственного интеллекта и анализа данных.
